## Requested reporting behavior

- SQL means an opportunity that entered the Sales Outreach SQL definition for the selected reporting window.
- Every SQL is classified by how the meeting was booked: **SDR** or **Calendar link**.
- SDR rows identify the user who actually created/booked the appointment. Do not use the assigned appointment owner as a proxy unless GHL confirms those are the same actor for the relevant record.
- Calendar-link rows show calendar/link name and UTM values. A missing UTM is a tracking defect on a known Calendar link booking, not an Unknown booking source. Booking-path coverage remains 100%; expose missing UTM as a repair signal.
- Include the default **Regulated Ads On Social/Search** calendar, **Book a demo** (`WS6lacfQK2XOhqN7mRaF`), and every calendar/link actually used in the vertical email campaigns. Build the final registry from a fresh GHL calendar/link readback and the saved email templates/workflows; do not assume these two are the full list.
- Email Trigger Link clicks should update campaign-touch attribution on the contact and create auditable click-source facts while preserving original acquisition source. A click is not itself a booked SQL.

## How to identify the SDR who booked

Inspect appointment payloads and workflow/UI history for the appointment **creator/booker user ID**, then resolve that ID through the GHL users list/report SDR registry. Also retain the assigned owner ID separately: a booking can be created by one SDR and assigned to another. Confirm whether GHL exposes a creator/booker field and whether it is stable after reschedule. If the API exposes only assigned owner, do not label it “booked by”; add an explicit capture step to the booking process/workflow or mark the actor unavailable until recorded.

Join the appointment to the SQL opportunity/contact using contact ID and the event timeline, and retain appointment ID, opportunity ID, create/start/update times, status, calendar ID, creator ID, assigned owner ID, and reschedule lineage. Deduplicate appointment reschedules for counts without discarding their raw records.

Use link ID/name as an additional durable key. Keep values URL-encoded and verify they survive every redirect into the booking widget and appointment/contact record.

### GHL workflow pattern

1. Inspect the existing Alcohol and Nicotine Trigger Link Source Attribution workflows, their trigger filters, actions, and current Contact `source` writes. Existing notes say the Nicotine workflow writes Contact `source` to a campaign label; do not extend that behavior blindly because it can overwrite original source and cannot represent multiple touches. Verify the Alcohol workflow state as well.
2. Agree the attribution field model and create fields only after checking existing GHL custom fields. Preserve original/first-touch source. Add distinct latest campaign-touch fields (vertical, campaign, medium, content/link key, trigger-link ID/name, UTM values, click timestamp) and retain an append-only click event ledger if the available GHL/n8n path can store it reliably.
3. Build a Trigger Link Clicked automation filtered by exact trigger-link ID. Prefer one shared workflow with explicit branches only if GHL supports exact link-ID filters and branch readback is unambiguous; otherwise use one small workflow per link or per campaign. Each branch writes the matching campaign-touch fields and records the click event idempotently. Repeated clicks update latest-touch fields and must not overwrite first-touch fields.
4. Keep click attribution separate from booking attribution. The booking appointment's calendar/link and captured UTMs establish Calendar link booking; a trigger-link click can be joined to it as supporting touch evidence. Do not mark a contact SQL or booked merely because a link was clicked.
5. Verify workflow behavior with a controlled test contact and a test click only after the link inventory, field map, and write behavior are reviewed. Verify the click event, contact fields, redirect URL, and resulting appointment UTM values. Then enable the automations for production links, and monitor missing-UTM calendar bookings.
